# Yanibox

Сайт стримера Yanibox. На главной собраны ссылки на фильмы, рейтинг времени просмотра и канал Twitch. Для нового раздела добавь карточку в список `home-grid` в `index.html` и включи файлы раздела в `publicFiles` в `scripts/build-pages.mjs`.

## Сайт

В настройках репозитория выбери **Settings → Pages → GitHub Actions**. Витрина и панель публикуются процессом **Publish Yanibox** при каждом обновлении `main` и по расписанию два раза в час.

Локальная проверка из папки проекта:

```powershell
python -m http.server 8765 --bind 127.0.0.1
```

Открой `http://localhost:8765/` для главной, `/films.html` для фильмов, `/profile.html` для профиля или `/admin.html` для панели стримера. Для запуска из `dist` сначала выполни `npm ci --ignore-scripts` и `node scripts/build-pages.mjs`.

## Фильмы и публикация

1. Создай [fine-grained token](https://github.com/settings/personal-access-tokens/new) в аккаунте Yanibox с доступом только к репозиторию `yanibox` и правом **Contents: Read and write**.
2. Введи токен на экране входа. Панель проверяет аккаунт на GitHub и держит токен в памяти открытой страницы. После перезагрузки или возврата из Twitch войди в панель ещё раз.
3. Добавь фильм. Можно указать зрителя, категорию, статус, оценку, длительность и заметку. Для прошлых просмотров укажи **Дату просмотра**. Каталог показывает её на карточке и умеет сортировать фильмы по этой дате.
4. Нажми **Сохранить и опубликовать**. Панель отправит весь список и покажет, когда новая версия появится на витрине. Чтобы отложить публикацию, нажми **Сохранить черновик**. Накопленные изменения можно отправить кнопкой **Опубликовать**.

Черновик хранится в браузере. Если список уже меняли в другом браузере, панель предупредит о конфликте и сохранит черновик. Кнопка **Загрузить с GitHub** подгружает актуальную версию. При наличии черновика панель спросит, можно ли его заменить. Фильмы, ники, заметки и оценки из опубликованной версии видны посетителям.

После ввода названия панель ищет постер через Wikidata и Кинопоиск, показывает его в форме и сохраняет вместе с фильмом. Для одноимённых фильмов указывай год, например «Дюна (2021)». Если подходящей обложки нет, в форме можно указать прямую HTTPS-ссылку на изображение. Свою длительность можно задать в минутах. Публичная витрина подхватывает опубликованные изменения примерно раз в минуту в открытой вкладке.

У заказа в очереди нажми **Запланировать**, выбери дату и при желании время показа по Москве, затем нажми **Сохранить и опубликовать**. Фильм появится в статусе **Запланирован** с датой на публичной карточке. После показа укажи дату просмотра. В фильтре **В очереди** старые заказы идут первыми по умолчанию. В меню витрины можно выбрать зрителя и изменить сортировку.

## Заказы за баллы Twitch

1. В [консоли Twitch](https://dev.twitch.tv/console/apps) зарегистрируй приложение. Впиши адрес возврата, который показывает панель рядом с кнопкой **Копировать**.
2. В настройках баллов канала включи обязательный ввод текста у каждой награды для заказа фильмов.
3. Вставь **Client ID** в панель и войди под аккаунтом владельца канала. После возврата введи токен GitHub для входа в панель и отметь все нужные награды. Статус **Слушает награды** покажет число выбранных. Название награды сохранится в заказе.
4. Оставь панель открытой на время стрима. Зритель активирует награду и вводит название. Фильм сразу попадает в черновик, а если включена автоматическая публикация, панель сама опубликует очередь.

Одна активация добавляется один раз. При обрыве связи панель переподключается, но Twitch не воспроизводит пропущенные события. Если заказ пропущен, его можно перенести вручную из очереди наград Twitch. Статусы фильмов меняются на сайте, а выполнение и возврат баллов ведутся в Twitch.

## Оценки зрителей

Гости видят оценку стримера, среднюю зрительскую оценку и число голосов. Чтобы оценить просмотренный фильм, зритель входит в профиль Yanibox и подтверждает Twitch через чат. Один Twitch ID может поставить от 1 до 10 и изменить свою оценку. Публичный API возвращает сводку по фильмам. Личная оценка доступна после входа в профиль с подтверждённой привязкой.

1. Создай проект Supabase и примени миграции из `supabase/migrations` по порядку через SQL Editor.
2. Сгенерируй 32 случайных байта в виде 64 строчных шестнадцатеричных символов. Сохрани эту строку как секрет GitHub Actions `YANIBOX_RATINGS_SYNC_KEY`. Сохрани в `viewer_ratings.sync_config.key_hash` только SHA-256 от текстовой строки. Для хеша в шестнадцатеричном виде используй `insert into viewer_ratings.sync_config (key_hash) values (decode('<хеш>', 'hex')) on conflict (singleton) do update set key_hash = excluded.key_hash;`.
3. В GitHub Actions добавь переменные `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY`. После настройки функций профиля выставь `SUPABASE_RATINGS_ENABLED` в `true` и запусти **Publish Yanibox**. При каждой публикации процесс передаёт Supabase список фильмов со статусом **Посмотрели**.

Код витрины использует публичный ключ. Ключ синхронизации в GitHub Actions разрешает обновлять список доступных для голосования фильмов.

## Профиль зрителя

Во вкладке **Профиль** зритель регистрируется с логином и паролем Yanibox. Почта для профиля не нужна. Сервер хранит хеш пароля Argon2id с отдельной случайной солью для каждого аккаунта.

Ранее созданный профиль с ключом доступа можно перевести на пароль после входа или со старым кодом восстановления. При переходе старый ключ, код и прежние сессии отзываются. У новых аккаунтов пока нет сброса забытого пароля.

Регистрировать Twitch можно отдельно. Функция ищет постоянный Twitch ID по введённому логину и выдаёт команду `!привязать КОД` для чата Yanibox. Код действителен пять минут и подходит только для ожидаемого Twitch ID. WizeBot по-прежнему поставляет часы и сообщения по текущему логину. При смене ника часы и сообщения за старые периоды могут отображаться частично. Смайлы считаются по ID.

Порядок перехода для действующего сайта:

1. Добавь в секреты Edge Functions `TWITCH_CLIENT_ID` и `TWITCH_CLIENT_SECRET` приложения Twitch с серверным доступом. Функция использует их для поиска публичного логина и ID. Введи значения в Supabase, серверу сайта они передаются как переменные окружения. Секреты и токены зрителей в витрине не используются.
2. Примени миграции `viewer_passkeys`, `viewer_chat_webhook` и `viewer_password_login` по порядку. Первая переносит прежние голоса по подтверждённому Twitch ID и закрывает запись через старую Twitch-сессию.
3. Разверни `viewer-profile` и `twitch-emotes` с `--no-verify-jwt`. Функция профиля сама проверяет пароли и сессии. Production origin по умолчанию `https://yanibox.github.io`. Для изолированной проверки укажи `YANIBOX_PROFILE_ORIGIN` на проверочном проекте. Убедись, что EventSub подписан на чат и функции доступны, затем опубликуй витрину.
4. После проверки новой регистрации, привязки и оценок отключи провайдер Twitch в **Supabase → Authentication → Sign In / Providers**. Старые учётные записи Supabase требуют отдельного решения об удалении.

Для сообщений из Twitch примени миграции `viewer_emotes` и `viewer_chat_webhook` и разверни функцию командой `supabase functions deploy twitch-emotes --no-verify-jwt`. При настройке через сервер `yanibox_chat_prepare` сохраняет ключ проверки подписи в Supabase Vault. При ручной настройке можно задать в Edge Functions секреты `TWITCH_BROADCASTER_ID` и `TWITCH_EVENTSUB_SECRET` (случайная строка длиной от 10 до 100 символов). Функция проверяет подпись Twitch для каждого запроса.

Создай [подписку Twitch EventSub](https://dev.twitch.tv/docs/chat/authenticating/#making-the-subscription) типа `channel.chat.message`, версии `1`. Укажи ID канала в `broadcaster_user_id`, ID авторизованного аккаунта бота в `user_id`, транспорт `webhook`, адрес `https://<project-ref>.supabase.co/functions/v1/twitch-emotes` и тот же секрет. Для этой подписки приложению нужны разрешения `user:read:chat` и `user:bot` от аккаунта бота, а также `channel:bot` от владельца канала либо статус модератора у бота. Для создания подписки используй App Access Token того же приложения. Счётчик хранит количество нативных смайлов Twitch с момента подключения. Тексты сообщений не сохраняются.

## Время просмотра

Вкладка **Время просмотра** показывает публичный рейтинг канала [Yanibox на WizeBot](https://yanibox.streaming.lv/?channel_tops&type=uptime&period=global). Доступны поиск по нику и фильтры топ-3, топ-5 и топ-10. Поиск внутри топа сохраняет исходные места.

GitHub Actions загружает рейтинг дважды в час и при публикации из `main`. Если WizeBot временно недоступен, сборка сохраняет последние опубликованные данные с датой их получения. В ветке `watchtime-history` сохраняется первый успешный снимок общего рейтинга за каждый день по Москве.

Прошлая неделя (пн–вс), последние 3 и 12 месяцев и выбранные даты считаются приблизительно по разнице общего времени на двух границах периода. Последняя дата включается. Для периода до сегодняшнего дня берётся свежий снимок, а для завершённого периода — первый снимок следующего дня. Витрина показывает время обоих замеров и сообщает, когда для диапазона не хватает истории. Сравнение выполняется по нику Twitch, поэтому смена ника или сброс времени могут повлиять на результат.

Для локальной проверки выполни `node scripts/build-pages.mjs` и запусти локальный сервер из папки `dist`. Для проверки архива установи `WATCHTIME_HISTORY_DIR` на отдельную папку со снимками.
